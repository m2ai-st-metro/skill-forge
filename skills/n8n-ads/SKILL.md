# n8n-ads: workflow → pain-point ad short

A content factory whose raw material is n8n workflows. Each run produces ONE ~30-60s
vertical short (single creative, exported for YT Shorts / IG Reels / TikTok) plus captions.
Veo clip generation is fully HIL: this skill writes the prompts, Matthew generates clips in
Flow (Google Ultra subscription), the skill resumes when clips land. No Veo API calls in v1.

## State model (stage-resumable)

All state lives in one project dir per workflow:

```
~/content/n8n-ads/<YYYY-MM-DD>-<slug>/
  source/          copy of the workflow file
  analysis.md      stage 2 output
  script.md        stage 3 output (ad script + hyperframes composition brief)
  veo-prompts.md   stage 3 output (copy-paste shot prompts)
  clips/           stage 4: Matthew drops downloaded Flow clips here
  clips/CHECKLIST.md   shot → expected filename mapping
  draft/           stage 5 hyperframes render(s)
  final/           stage 6 exports + captions.md
```

**On every invocation**: if Matthew names/implies an in-flight workflow, find its dir under
`~/content/n8n-ads/` (Glob), infer the stage from which files exist, and do the NEXT stage
only. Never redo an approved stage unless asked. Sessions dying mid-run is expected and fine.

The Drive library mirror lives at `~/content/n8n-ads/_library/` with `catalog.md` beside it.

## Stages

### Stage 1 — Intake (once, then on demand)

If `_library/` doesn't exist or Matthew asks for a re-sync:
1. Ask for the Drive folder path if unknown, then `rclone copy "gdrive:<folder>" ~/content/n8n-ads/_library/`.
2. Build/refresh `_library/catalog.md`: one line per file — filename, guessed domain
   (from filename + a quick skim of node names), signal-richness guess (rich / medium / bare).
Per run: Matthew picks the workflow (or asks for a suggestion — prefer rich-signal,
un-run files). Create the project dir, copy the file to `source/`.

### Stage 2 — Analysis → `analysis.md` (HIL gate)

Read the workflow file. .json parses as an n8n export (nodes, connections, sticky notes);
.txt may be a JSON dump or prose — handle both. Reconstruct:
- What the workflow DOES (trigger → transforms → outputs, in business language, not node names)
- **The pain point it solves** — the "what breaks in the business without this" sentence
- **Audience classification**: `business-owner` (SMB owner feeling the operational pain) or
  `creator` (non-technical content creator: posting, repurposing, DM/fan management).
  Pick ONE per video. Creator-market ads stay fully SFW and platform-compliant: frame as
  "content creator business automation"; niche-specific messaging belongs in the funnel,
  never in the video.
- **Signal score 1-5**: how confidently the business pain can be inferred. Score < 3 →
  write a SKIP verdict into `catalog.md` with reason and stop; pick another workflow.
  Skipping is a legitimate exit, not a failure. Do not hallucinate a use case.

Use the template in `references/templates.md`. **Gate: Matthew approves the pain-point
angle and audience (or redirects) before stage 3.**

### Stage 3 — Script + shot pack → `script.md`, `veo-prompts.md` (HIL gate)

Read `references/veo-prompting.md` FIRST (grounded 2026-08-13 from ai.google.dev; if
Google has shipped a newer Veo generation since, verify current guidance before writing prompts).

`script.md` — pain → agitate → reveal arc for 30-60s vertical (see template):
- Hook (0-3s): name the pain, visually and in overlay text
- Agitate (3-15s): the grind, the cost, the repetition
- Reveal (15-40s): the automated outcome (outcome, not n8n mechanics — n8n is never named
  for business-owner audience; optional light mention for creator audience)
- CTA (final 5s)
Plus a **hyperframes composition brief**: per-beat overlay text, caption style, brand
elements, CTA card, pacing notes.

`veo-prompts.md` — 4-7 shot prompts, each:
- **Self-contained**: no recurring named characters across shots (identity drift is a known
  Veo/synthetic-video failure — prefer hands, screens, environments, different people per shot)
- Written in Veo grammar (subject / action / style / camera / ambiance / audio), 30-80 words,
  9:16 explicitly stated, 8s duration assumed (trim in assembly)
- Copy-paste ready in a fenced block, one per shot, with shot number + expected filename
  (`shot-01.mp4`...)

Also write `clips/CHECKLIST.md` mapping each shot to its filename with a review criterion
per shot ("what must be visible for this clip to pass").

**Gate: Matthew approves the shotlist before generating anything.**

### Stage 4 — Clip generation (fully HIL, Matthew's stage)

Matthew pastes prompts into Flow, downloads clips into `clips/` per the checklist.
When re-invoked: verify clips against `CHECKLIST.md`. Missing/failed shots → offer a
corrective regenerated prompt (adjust the specific failure, don't rewrite the shot).
Take budget: 2 regeneration rounds per shot, then simplify the shot or cut it from the edit.

### Stage 5 — Assembly (HIL gate)

Invoke `/hyperframes` with the composition brief + `clips/`: 9:16, captions, typography
beats from the brief, CTA card, render to `draft/`. **Gate: Matthew watches the draft;
notes → iterate (2 rounds, then discuss rather than grind).**

### Stage 6 — Package → `final/`

- Export the approved render for the 3 platforms (all 9:16; usually the same MP4, but check
  duration fits each platform's shorts limits)
- `final/captions.md`: per-platform caption, hashtags, hook text, CTA line (see template)
- Append a done-line to `catalog.md` (workflow → project dir → date)
Pipeline ENDS at files. Posting is manual; Late API draft-scheduling is the documented v2.

## Failure table

| Scenario | Detect | Recover |
|---|---|---|
| No inferable business context | Signal score < 3 | SKIP verdict in catalog, next workflow |
| Malformed/truncated file | JSON parse fails / ~0 nodes | Infer from filename + prose, flag low confidence at the gate |
| Veo clips drift from shotlist | Checklist review | Corrective re-prompt, max 2 rounds, then cut/simplify shot |
| Session dies mid-run | Always survivable | Stage inferred from files on next invocation |
| Creator ad reads adult-adjacent | Script-gate checklist | Reframe to generic creator-business language before render |
| Stale Drive mirror | Matthew says library changed | Re-run stage 1 sync |

## Explicit non-goals (v1)

No Veo API integration, no auto-posting, no n8n troubleshooting/building, no batch runs,
no multi-angle A/B variants per workflow. Revisit after real performance data.
